About this demo

The question: Machine Learning classifiers don't just output labels; they output probabilities. Choosing a threshold of 0.5 is rarely optimal when the business costs of errors are asymmetric.

Try it: Drag the threshold slider. Observe how lower thresholds catch more converters (higher Recall) but increase false alarms (lower Precision, costing user friction). Watch the confusion matrix adjust in real time.

Cost view:By modeling the costs (+$100 per conversion, -$20 per false alarm friction, -$150 per missed conversion), you can find the mathematical point that maximizes net returns, which occurs at the 0.35 threshold.

Data Platform & ML Operations

How data gets checked, versioned, streamed and scheduled, and how a model is watched after launch. Each demo below starts with a short "try this" so you know what to press.

Job Description Fit Scorer

Paste a job description and see how well it matches this profile, with each requirement checked against real work.

  1. Pick a sample job, or choose "My own job description" and paste one.
  2. Press Score this job.
  3. Read the table: every skill the job asks for, and where it shows up in the profile.

What you paste stays on this page. Nothing is sent anywhere.

Same rules as fit_service.py in Career Pilot, where they keep the AI's match score honest. Every deploy checks that this page gives the same scores as the Python original.

Data Contract & Quality Checker

Before a new file of job postings is used, check it against rules learned from a file you trust: no missing values, no duplicate IDs, salaries in a normal range, known categories only.

  1. Leave "Monday's file" as the good example the rules are learned from.
  2. Pick a day's file to check (Tuesday and Wednesday have problems hidden in them).
  3. Press Check the file and see which rules broke, and on which rows.

A file you choose is read on this page and never uploaded. Up to 5 MB.

The Job Market Lakehouse runs rules like these with Great Expectations after every PySpark job. A failed check stops the pipeline before bad data reaches a report.

SCD Type 2 Snapshot Builder

A customer table only shows today's values. A history table (a "Type 2 slowly changing dimension") keeps every past version too, so you can answer "which city was this customer in last month?"

  1. Press Save a snapshot to record today's table.
  2. Change a customer's city or tier in the table above it, or delete a customer.
  3. Save again and watch the history table: the old row gets an end date and a new current row appears.
How to spot a change

Today's table: customers

History table: customers_snapshot

This is how a dbt snapshot works. The dbt warehouse keeps its daily pipeline table with an incremental merge instead, which keeps only the latest value. That's the trade-off this demo shows.

Model Drift & Fairness Monitor

A loan-approval model was trained on last year's applicants. When this year's applicants look different, or one group is treated worse, a monitor should notice. Both checks are below, each with its own controls.

Part 1: did the new applicants change?

  1. Pick a feature.
  2. Drag Move the average left or right.
  3. The status next to each feature turns red once the change is big enough to act on.

Part 2: is the model fair to both groups?

  1. Drag Approval cut-off: applicants scoring above it are approved.
  2. Watch both groups' bars move. A red note appears when the gap breaks a fairness rule.

Same limits as the AI Model Observability audit engine: PSI over 0.25, a KS test p-value under 0.01, the four-fifths rule, and a 10-point gap in true-positive rate. The applicants are generated on this page.

Lakehouse Time Travel Explorer

Lakehouse tables (Apache Iceberg, Delta Lake) never overwrite data in place. Every change saves a new version, so you can query the table as it was before a mistake.

  1. Press Add 3 rows twice, then Give one company a 10% raise and Delete the lowest salary.
  2. Click any earlier version to see the table exactly as it was then.
  3. Press Tidy up files, then Delete old versions, and see what time travel loses.
How changes are written

A simulation of how the format behaves. The real Delta Lake and Iceberg tables are in TalentVenue EventIntel's table_formats.py.

Streaming Event-Time Window Simulator

Machine sensors send a temperature reading every few seconds, and a stream job averages them per 10-second window. Some readings get stuck in the network and arrive late. How long should the job wait before it publishes a window's average?

  1. Press Replay the stream and watch the dots arrive, top to bottom.
  2. Set Wait for stragglers to 0 and replay: more readings are dropped.
  3. Tap a dot to delay that reading by 8 seconds.

"Wait for stragglers" is the watermark delay and "accept late readings" is the allowed lateness, the two settings a stream engine uses to decide this. The IoT telematics pipeline writes its telemetry in event-time order in micro-batches.

Airflow DAG Backfill & Retry Replay

A pipeline runs three steps every day: create the data, transform it with PySpark, then check it. Here it catches up on five missed days at once (a backfill), and some steps fail along the way.

  1. Press Run the 5 days. Two failures are already set up.
  2. Red squares failed; orange ones never ran because an earlier step failed. Tap a square to read its log.
  3. Press Fix it and re-run on a failed square, or add retries and run again.
Set up your own failures

    The three steps are the real tasks of the Job Market Lakehouse Airflow DAG. The real DAG runs on demand; this replay puts it on a daily schedule so retries and backfills have something to show.

    Trained Models, Running in Your Browser

    These are the projects' own trained models, not re-creations. They download only when you press Run, then run on this page; nothing you draw or show them leaves your device.

    Shape Classifier

    A small CNN that names the shape in a 64 x 64 image (circle, square, triangle, rectangle, pentagon, hexagon or star) and draws a box around it. It scored 99.20% on 2,000 held-out images.

    1. Pick a test shape below, or switch to Draw your own.
    2. Press Run the model. The first run downloads it (about 3 MB).
    3. Read the scores for all 7 shapes, and the box the model drew.
    Input

    Draw one filled shape with your finger or mouse. Your drawing is not like the training images (those are clean, filled and slightly noisy), so expect lower accuracy here; the 99.20% applies only to the test shapes.

    ASL Word Signs

    Recognises 29 STEM and computing signs (computer, email, science, math...) from about two seconds of video. On 58 held-out clips the right sign was the top guess 75.86% of the time and in the top three 94.83% of the time (chance is 3.45%).

    1. Pick a held-out clip, or switch to Use your camera and sign one of the words listed below.
    2. Press Recognise the sign.
    3. Read the top three signs. The picture shows the hand points the model reads, frame by frame.
    Input

    The camera runs only on this page: frames are read in your browser and are never uploaded or saved. The first start downloads MediaPipe's hand model and OpenCV.js (about 14 MB). Sign with your hands fully in view and good light; a phone works, but more slowly.

    Signs it knows: computer, internet, email, program, network, machine, print, television, write, letter, paper, test, learn, study, teacher, school, science, math, calculate, research, measure, plus, energy, chemistry, biology, physics, experiment, book, picture.     Project Statistics, Recomputed in Your Browser

    Each project's own data, with its statistical tests rewritten to run on this page. Change the inputs and the tests rerun; every deploy checks the page's numbers against the Python libraries the projects use.

    Survival Curves by Dosage

    A simulated 365-day trial of 250 patients in three arms. Filter the patients and compare arms: Kaplan-Meier curves show the share still alive each day, the log-rank test asks whether two curves differ, and the chi-square test asks whether adverse-event rates differ.

    1. Choose patients by gender and age.
    2. Tick the arms to compare.
    3. Read the curves, then the tests below them. A dropping line means patients dying; the dashed line marks half still alive.
    Arms

    From Clinical Trials Patient Outcomes Analysis (FINDINGS). The patients are simulated with a fixed seed; none are real. An adverse event is the project's own rule: systolic blood pressure under 105 or over 155 at any visit. Every deploy checks the page against lifelines and SciPy on all 12 gender and age filters.
