Seven more demos

Each one runs in your browser on sample data you can change, and works out its numbers from what you do here. Each one also links to the repo where the real version runs.

Job-fit explainer

Paste any job posting to see how well it fits this profile, with every requirement traced to the work that backs it. This is the same rule set Career Pilot's fit_service.py uses to keep its AI score honest: 60% skill overlap, 20% role type, 20% years asked for, and a cap of 40 when the role type isn't one this profile targets. A check scores the port against the Python original on every sample.

What you paste stays in this page. Nothing is sent anywhere.

Data contract checker

Learns a contract from a reference batch (columns, types, nulls, unique keys, ranges, allowed values), then checks a new batch against it and shows the failing rows. The expectations use Great Expectations' names; the Job Market Lakehouse runs the real suite after every PySpark transform.

Your file is read in this page and never uploaded. Files up to 5 MB.

SCD Type 2 snapshot

Edit the source table, then take a snapshot: a changed row gets its old version closed and a new current one opened, the way a dbt snapshot keeps history. The dbt warehouse keeps its daily pipeline table with an incremental merge instead, which keeps only the latest value. That's the trade-off this demo shows.

Model drift and fairness board

Shift one feature of a new batch of loan applicants and watch PSI and the KS test pick it up, the model's per-feature contributions move, and approval and true-positive rates change by group. The thresholds match the AI Model Observability audit engine: PSI over 0.25, KS p below 0.01, the four-fifths rule, and a 10-point true-positive-rate gap. The applicants are generated in this page.

Table format time travel

Commit appends, updates and deletes to an Iceberg-style table, then query it as of any snapshot and watch the metadata tree and data files change. This is a simulation of the format. The real Delta Lake and Iceberg tables are in TalentVenue EventIntel's table_formats.py.

Event-time windows

Sensor readings arrive out of order. Choose a window type, how far the watermark trails the newest event, and how long a closed window still accepts late readings. Then step through arrival time and see each reading counted, counted late, or dropped, with the reason. The IoT telematics pipeline writes its telemetry in event-time order in micro-batches. This demo shows what a streaming engine decides when readings come in late.

Tap a reading to hold it back 8 seconds in the network; tap it again to undo.

DAG scheduler replay

The three tasks of the Job Market Lakehouse Airflow DAG (generate, PySpark transform, Great Expectations validation), backfilled over five days. Make a task fail, set retries, and read the grid the way the Airflow UI shows it. The real DAG runs on demand; the replay puts it on a daily schedule so retries and backfill have something to show.
