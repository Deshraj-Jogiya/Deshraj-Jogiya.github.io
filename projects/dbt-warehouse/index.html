Job Search dbt Warehouse: a dimensional model on Databricks

A dbt project that builds a dimensional model on a Databricks SQL warehouse: staging views over seed data, dimension and fact tables, an incremental daily snapshot, and data tests that run against the warehouse.

Result
22 data tests against a live Databricks warehouse
Built for
Anyone tracking a job search who wants answers like days from application to decision, and pipeline counts by day.
Role
Sole developer: design, build, tests and deployment
When
Sep 2026
Code on GitHub ↗

How it works

  1. Four seed files (companies, postings, applications, interview rounds) load into staging views
  2. dim_company, dim_job_posting and dim_date (a 2025 to 2027 date spine built with sequence() and explode())
  3. fct_application with a datediff days-to-decision measure, and fct_interview_event with a row_number() round sequence
  4. fct_daily_pipeline_snapshot, an incremental model that merges on date so later runs only recompute new days

Data

Synthetic seed data describing a job search; not a real company's data.

Problems found and decisions made

A full rebuild of the daily snapshot grows with every day of history
The snapshot is incremental and merges on date_day.
Generic tests can't express business rules
Two singular tests: a decision date never precedes the applied date, and snapshot counts never go negative.
The original workspace ran out of trial credits
The project moved to Databricks Free Edition, and credentials are read only from environment variables.

Testing and reliability

  • 22 dbt tests: 20 schema tests (6 unique, 9 not-null, 4 referential-integrity, 1 accepted-values) and 2 business-rule tests
  • CI runs dbt seed, dbt run and dbt test against the warehouse in a separate CI schema

Results

  • A working dimensional model with an incremental snapshot
  • All 22 tests passing when the warehouse is reachable

Limits and next steps

  • CI depends on the Databricks workspace being reachable; when it isn't, the run fails on the connection rather than on the model
